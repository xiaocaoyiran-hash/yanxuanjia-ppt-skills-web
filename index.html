3在 WorkBuddy 等各类 Agent 里用

          

            

              
通用三件事

              
    
                
  1. 拿到 skill：详情页复制安装命令，或直接 git clone / 下载 zip。
    2. 
                
  2. 放对位置：skill = 一个含 SKILL.md 的目录。用户级放 ~/.workbuddy/skills/，项目级放 {项目}/.workbuddy/skills/。认目录不认命令。
    3. 
                
  3. 自然语言触发：不用记参数，直接说需求 + 风格 ID。
    4.

4八条原则 —— 这个领域最可靠的信号

          

            
1先定路线，再谈风格。能不能编辑是硬约束，审美是软变量。

            
2star 不是质量。它衡量关注度，只适合当第一层筛子。

            
3人工核读过 SKILL.md 的，可信度高一个档。文档写了什么，比 README 宣传什么重要。

            
4能力矩阵里的「·」只是没写。别把沉默当否定。

            
5样图是宣传帧，不是横评。每家都挑自己最好看的那一页。

            
6Copyleft 先看协议。AGPL 用在内部汇报没问题，别顺手嵌进对外产品。

            
7模板能救 80% 的场合。剩下 20% 才需要从零设计。

            
8先给 3 个方案再挑。别人替你决定风格，通常都不对。
